# Hackathon Rules Check

**Action required before presenting:** verify iFX Hack Hong Kong 2026's
official rules on pre-built code and AI-assisted development.

## Why this file exists

This repository's initial bootstrap (backend, frontend, demo data,
documentation, CI, project scaffolding) was generated in a single session
before/around the official hackathon start. Many hackathons:

- allow unlimited pre-work but require it to be disclosed in the pitch,
- allow a scaffolded starting point but require the core feature work to
  happen during the event window, or
- require all code to be written during the event, with no exceptions.

**We do not know which of these applies to iFX Hack Hong Kong 2026.**

## What to do

1. Find the official rules (event website, Discord/Slack, organizer email)
   and read the section on pre-built code / starter templates / AI
   assistance.
2. Record the finding here (replace this section):

   > Rules checked on: `<date>` by `<name>`. Source: `<link>`. Summary:
   > `<what's allowed>`.

3. If disclosure is required, say so plainly in the pitch: what existed
   before the event window (this scaffold, the demo data, the deterministic
   engine) versus what was built during it (the P1 differentiator, UX
   polish, any new integration).
4. If pre-built code beyond a certain scope is disallowed, flag this to
   the team **before** the event — don't discover it during judging.

## Principle

Do not misrepresent pre-existing work as created during the hackathon if
event rules prohibit or require disclosure of that. When in doubt, over-
disclose.
